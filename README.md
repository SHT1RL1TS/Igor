# Igor

Демонстрационный мессенджер: React + Vite, Express + Socket.IO, PostgreSQL.
Все команды ниже выполняются из папки проекта `D:\igor`, если не указано иное.

## Запуск у друга через Docker

1. Установить и запустить Docker с поддержкой `docker compose`.
2. Проверить корневой `.env`: `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_PORT`.
   Существующий файл сохранён. Если его нет, скопировать `.env.example` в `.env`
   и задать пароль. При занятом порте 80 добавить `HTTP_PORT=8081`.
3. Выполнить:

   ```powershell
   cd D:\igor
   docker compose up -d --build --remove-orphans
   docker compose ps -a
   ```

4. Открыть **http://localhost** (или http://localhost:8081 при `HTTP_PORT=8081`).
   Для адреса `http://igor.com` дополнительно нужна запись `127.0.0.1 igor.com`
   в системном файле hosts; для `localhost` это не требуется.

`--remove-orphans` убирает контейнер отдельного Nginx из старой конфигурации,
который иначе может продолжать занимать порт 80. Теперь готовую сборку и
проксирование API/WebSocket обслуживает Nginx внутри контейнера `frontend`.
Фронтенд ждёт готовности backend, backend — завершения инициализации базы.
Успешный статус `db-init` — **Exited (0)**: это одноразовая задача.

После изменения файлов снова выполните команду сборки выше и обновите страницу
с `Ctrl+F5`. Каталоги `node_modules` с Windows не используются в Linux-контейнерах.
Данные сохраняются в томе `pg_data`; для остановки используйте `docker compose down`
**без `-v`**, чтобы не удалять переписку.

Если сервер не запускается:

```powershell
docker compose logs --tail=100 db db-init backend frontend
```

При существующем томе PostgreSQL значения пользователя, имени базы и пароля в
`.env` должны соответствовать значениям, с которыми этот том был создан.

## Проверки без Docker и установленного PostgreSQL

Требуется Node.js **22.12 или новее**. Установите зависимости обеих частей:

```powershell
npm --prefix backend ci
npm --prefix frontend ci
npm --prefix backend test
```

Серверные тесты выполняют настоящий SQL в отдельной базе PGlite в памяти,
проверяют HTTP API и Socket.IO. Они не подключаются к вашей основной базе.

Для браузерных тестов можно использовать установленный Microsoft Edge:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm --prefix frontend test
```

Или установить тестовый Chromium и использовать его:

```powershell
cd frontend
npx playwright install chromium
Remove-Item Env:PLAYWRIGHT_CHANNEL -ErrorAction SilentlyContinue
npm test
```

Тесты сами собирают обе части, создают временную базу и запускают фронтенд
на портах 13000 и 13001. Проверяются режим разработки и готовая сборка.

Чтобы вручную посмотреть демо без Docker/PostgreSQL, откройте два терминала
в корне проекта:

```powershell
# Первый терминал: отдельная временная база, исчезает после остановки.
npm --prefix backend run test:serve
```

```powershell
# Второй терминал
$env:BACKEND_URL = 'http://127.0.0.1:18080'
npm --prefix frontend run dev
```

Откройте http://localhost:3000. Остановить оба процесса можно через `Ctrl+C`.
Этот тестовый режим не предназначен для хранения переписки.

## Локальный запуск с постоянной базой без Docker

1. Установить PostgreSQL 15+, создать пользователя и базу по настройкам `.env`.
2. Выполнить `postgres/init.sql` в этой базе через `psql` или pgAdmin.
   Повторное выполнение не удаляет существующие сообщения.
3. В первом терминале выполнить:

   ```powershell
   npm --prefix backend ci
   npm --prefix backend run build
   npm --prefix backend start
   ```

4. Во втором терминале выполнить:

   ```powershell
   npm --prefix frontend ci
   Remove-Item Env:BACKEND_URL -ErrorAction SilentlyContinue
   npm --prefix frontend run dev
   ```

Backend читает `.env` из корня; по умолчанию слушает 8080 и подключается к
PostgreSQL на `localhost`. Vite слушает 3000 и проксирует `/api`, `/avatars`
и `/socket.io` на `http://127.0.0.1:8080`. Если backend на другом адресе, задайте
`BACKEND_URL` в окружении фронтенда. Секреты базы не передаются в браузер.

## Что реализовано

- Профиль `SHT1RL1TS` загружается из базы по имени, а не по предположению `id = 1`.
- Демо-чаты 2 и 3 соответствуют `roton4ik` и `Nastya`.
- Сохранение сообщений через HTTP, доставка через Socket.IO, восстановление
  истории после переподключения, поиск по чатам и просмотр профиля.
- Проверка входных данных, понятные ошибки загрузки/отправки и повторные попытки.

Это демонстрационный проект с общим профилем, **без авторизации и разграничения
доступа к переписке**. Регистрация, выход из учётной записи и смена аватара в
исходном проекте не были реализованы. Неработающие кнопки этих действий заменены
пометкой о демонстрационном профиле.
